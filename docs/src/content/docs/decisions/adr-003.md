**Date**: 2026-09-13
**Status**: Decided

## Context

`VER-001` requires every mutating use case to land a new version while every earlier version stays readable; `VER-002` forbids a read or an export from mutating the store; `VER-003` asks for the ephemeral/kept distinction to exist in the store from day one, even though v1's only write path (a UI or API save) always produces a kept version.

## Decision

`backend/adapters/store/postgres.py` implements `PlanStore` over two tables (`backend/adapters/store/schema.sql`): `plans` (one row per plan id) and `plan_versions` (`plan_id`, `version` (an integer step, 1, 2, 3...), `dataset` (the full REF-Plan JSONB object), `ephemeral` (boolean, always `false` today), `created_at`). No code path in this module issues an `UPDATE` or a `DELETE` against `plan_versions` - checked directly by `tests/test_store.py`, which inspects the module's own source. `meta.version`'s display string (`"v0.1"`, `"v0.2"`, ...) is derived from the integer step at write time (`backend/domain/models.py::bump_version`), never typed by a caller.

## Rationale

- Two tables rather than one keep "does this plan exist" (for id-collision checks) separate from "what are its versions," without changing the append-only guarantee.
- Carrying `ephemeral` in the schema now, unused, is a zero-cost migration avoidance: a later draft-state feature (rb-plans#4) needs no schema change, only a new code path that writes `ephemeral=true`.
- Testing immutability by inspecting the store module's source (no `UPDATE`/`DELETE` string anywhere) is a cheap, precise proxy for "this code cannot mutate a row," independent of whatever data happens to be in the test database at the time.

## Alternatives considered and rejected

- **A single mutable `plans` table with a JSONB history array**: rejected because Postgres cannot enforce append-only semantics on an array column the way a dedicated table's own access pattern can be tested for, and a full-table row lock on every version write would serialize unrelated plans' writes against each other.
- **Soft-delete or an `is_current` flag**: rejected - `VER-001` requires every version to stay readable at its own content, and a flag invites exactly the in-place-edit anti-pattern `REF-Plan.md` anti-pattern 4 warns against.
