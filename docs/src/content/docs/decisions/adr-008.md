**Date**: 2026-09-21
**Status**: Decided

## Context

The engine holds no user directory of its own (BND-003): people are the identity realm's, and every app on the install fronts its human surfaces with an oauth2-proxy sidecar against its own realm (ADR-005). The machine door keeps the app's own key because an agent cannot complete an interactive sign-in. A key is a shared secret, not a person, so it is no sign-in for the cockpit or the REST API.

## Decision

- The chart always runs the sidecar, and the Service targets it (`k8s/templates/deployment.yaml`, `service.yaml`).
- The chart sets `PLANS_AUTH_SCOPE=mcp` beside it (INT-FOUNDRY-037). Under that value the sidecar fronts the human surfaces and the app's own key gates `/mcp`.
- Under any other value the app serves `/api/health` and the machine door only; the cockpit and the REST API answer `503`, so a misspelt value refuses rather than serving them open (INT-PLANS-043).
- `/api/agent-credential` is a human surface: it sits behind the sidecar with the cockpit (INT-PLANS-045).

## Consequences

A local run or the self-contained e2e stack declares the chart's shape (`PLANS_AUTH_SCOPE=mcp`) to use the cockpit with no sidecar in front.

## Alternatives considered and rejected

- **Let the app's key gate the human surfaces when no sidecar is in front**: rejected because it is a second identity for people beside the realm, shared by everyone who holds the key, and it would let a leaked machine key reach the human surfaces.
